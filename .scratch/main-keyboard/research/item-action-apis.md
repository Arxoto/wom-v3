# 四类候选动作的插件覆盖

来源：本机 Cargo registry 快照（`tauri-plugin-opener` 2.5.5、`tauri-plugin-clipboard-manager` 2.3.3）与本仓库文件。路径里的 registry 根为
`C:\Users\Jesus\scoop\persist\rustup-msvc\.cargo\registry\src\index.crates.io-1949cf8c6b5b557f\`。

## 结论速览

| 候选动作 | 官方路径 | 现状 |
| --- | --- | --- |
| 复制进剪贴板 | `tauri-plugin-clipboard-manager` 的 `write_text` | registry 里有源码，但**不是本仓库依赖** |
| 用默认浏览器打开 | `tauri-plugin-opener` 的 `open_url` | 已依赖、已注册，`opener:default` 已允许 |
| 用默认方式打开（文件/文件夹/应用） | `opener` 的 `open_path` | 已依赖，但 **`open_path` 不在 `opener:default` 里** |
| 在文件资源管理器中选中 | `opener` 的 `reveal_item_in_dir` | 已在 `opener:default` 里 |

## 关键机制：ACL 只拦 IPC，不拦 Rust 调用

- opener 的 IPC 命令会用 `CommandScope` / `GlobalScope` 构造 `Scope` 校验 URL，未通过返回 `ForbiddenUrl`（`tauri-plugin-opener-2.5.5\src\commands.rs` 开头）；而 Rust 侧 `app.opener().open_url(...)`（`OpenerExt`，`src\lib.rs:62` / `:116` / `:156`）**不经过这段校验**。
- clipboard-manager 的 `permissions\default.toml` 是空的，原文写着 "Clipboard interaction needs to be explicitly enabled."；但 Rust 侧 `app.clipboard().write_text(...)`（`src\desktop.rs:31`）可直接用。
- 所以：wom 的动作都在自家的 Rust 命令里执行（前端不直接调插件命令）时，**capabilities 不是网关**；需要的是 ① `Cargo.toml` 加依赖 ② `lib.rs` 注册插件。只有让前端直接 `invoke` 插件命令时，才需要权限项。

## 细节与来源

- opener 命令表：`src\lib.rs:229` 的 `generate_handler![commands::open_url, commands::open_path, commands::reveal_item_in_dir]`。
- opener 的 Rust API：`src\lib.rs:62` `open_url`、`:116` `open_path`、`:156` `reveal_item_in_dir`、`:160` `reveal_items_in_dir`。
- opener 权限：`permissions\default.toml` = `allow-open-url` + `allow-reveal-item-in-dir` + `allow-default-urls`（注释明确说这个集合覆盖 `mailto:` / `tel:` / `https://` / `http://` 与在文件管理器中揭示）；`permissions\autogenerated\commands\open_path.toml` = `allow-open-path` / `deny-open-path`，**不在默认集里**。
- 平台支持：opener 的 `README.md` 表格给 Linux / Windows / macOS / Android / iOS 全部 ✓；`revealItemInDir` 的 JS 绑定注释写明 Android / iOS 不支持。
- clipboard-manager 命令表：`src\lib.rs:44` 的 `generate_handler![commands::write_text, commands::read_text, commands::read_image, commands::write_image, commands::write_html, commands::clear]`；Rust API 见 `src\desktop.rs:31`（`write_text`）与 `:62`（`read_text`）。
- clipboard-manager 权限：`permissions\default.toml` 为空；`permissions\autogenerated\commands\write_text.toml` 提供 `allow-write-text`。
- 本仓库现状：依赖表见 `src-tauri\Cargo.toml`（opener 已在，clipboard-manager 不在）；已注册的插件见 `src-tauri\src\lib.rs` 的 `Builder::default()` 链；权限见 `src-tauri\capabilities\default.json`（`core:default`、`core:window:allow-start-dragging`、`opener:default`、`log:default`、`notification:default`）。

## 未证实

- WebView 里的 `navigator.clipboard` 在 Tauri 自定义协议下是否算安全上下文——没查（也不打算走这条路，动作在 Rust 侧执行）。
- macOS 上 `reveal_item_in_dir` 的实际表现（源码里有 macOS 实现分支，但没有实机验证）。

## 对 wom 的结论

- 四类候选动作都有官方实现路径：复制用 `tauri-plugin-clipboard-manager`（新增 Cargo 依赖），其余三个用已经依赖的 `opener`。
- 动作在 Rust 的自家命令里执行，就不需要改 `capabilities`；一旦改成前端直接 invoke 插件命令，`open_path` 还得单独加 `opener:allow-open-path`。
- 「用默认方式打开」与「在文件资源管理器中选中」是两个不同的官方 API（`open_path` vs `reveal_item_in_dir`），可以并存成两个动作。
