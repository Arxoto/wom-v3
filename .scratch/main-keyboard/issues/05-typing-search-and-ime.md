# 打字到检索的时序

Type: grilling
Status: resolved

## Question

打字怎么变成检索？合成期间哪些键放行？怎么防止响应乱序？按住方向键的连发怎么办？

## Answer

- **合成期间**：input 路径由 [IME 合成期间的事件语义](01-research-ime-composition.md) 定——`compositionstart` / `compositionend` 的 lock 挡住防抖与检索，`compositionend` 自己补一次检索（靠「文本没变不重发」去重）。keydown 路径暂不做合成判断：按「候选框打开时这些键到不了页面」的假设先实现，功能验收时再实测。按 ESC 取消候选却把窗口关了、按 Enter 提交候选却触发了动作，都是要盯的硬伤。
- **检索时机**：非合成变更后 50ms 尾触发防抖；文本与上次发送相同就不重发（后端另有 `input_key` 缓存兜底）。
- **乱序**：请求令牌只与「当前最新令牌」比相等，**不比较大小**；令牌用有界环计数器（如 `% 256`，远大于同时在飞的请求数），数字不会无限增长，回绕也不会误判。
- **连发**：按住 ↑/↓ 限流约 100ms（写成常量）；触控板的惯性滚动不在此列。

## Comments

- 2026-09-19：`searching` 的口径收窄成「发出去那一刻才挂」——`send` 里 `deps.search` 之前报 `on_search_pending(true)`；结果回来由 reducer 的 `page_loaded` 复位，失败与「到点却没发新的」（令牌已前进、在飞那一笔的响应会被丢弃）由会话补报 `false`。防抖那 50ms 不再算：首屏第一次输入、上一条零结果后再打字、合成结束补的那次，在这 50ms 里照旧显示「`N/A` / 没有匹配的条目」。下面两条里「排上防抖就挂」随之作废。
- 2026-09-19：「搜索中」这一档作废——**搜索期间与空输入是同一副样子**：列表区与右上角标签都留白。判据从两个组件的 props 里收成一个 `empty`，由 `AppMain` 现算（`input === "" || searching`），`Head` / `Body` 各只收这一个；`MainState.searching` 与 `on_search_pending` 保留，它只管「结果还在路上」。下面那条里「搜索中」那一档与标签的说法随之作废。
- 2026-09-19：列表为空时那句占位文案多了一档——结果还没回来时是「搜索中」，落到没匹配才是「没有匹配的条目」；右上角标签同理，结果没回来时不显示 `N/A`（`total` 还是上一条的值），留白，有结果时的「序号 / 总数」照旧。判据是 `MainState.searching`，由 `search_session` 的 `on_search_pending` 报：排上防抖（这次输入真会发检索）或第一页在飞时挂上，落定（结果回来 / 失败 / 这一轮不搜）收掉；空输入的清空那一轮不算。改动前打字到结果回来之间那句文案一律显示「没有匹配的条目」、标签闪 `N/A`，首屏第一次输入就能看到（见 [spec.md](../main-keyboard/spec.md) §2 / §3）。
- 2026-09-19：输入清空到空串改为**不检索**——尾防抖到点后 `send` 判空，不发请求而直接回调 `on_page_loaded(undefined)`，reducer 据此把结果整份清空（列表区提示输入搜索）；在飞的第一页与预请求同时作废、去重记录复位，清空后重打同一个关键字会重新搜。搜不搜与关键字怎么切（第一个空格之前）都在 `send` 里，以空格开头时关键字是空串即全量（见 [spec.md](../main-keyboard/spec.md) §3）。下面那条里「输入清空到空串仍照常检索」随之作废。
- 2026-09-18：首屏不再自动检索——挂载时那次空关键字请求去掉，列表空着直到第一次输入；输入清空到空串仍照常检索。`SearchSession` 的对外方法随之按事件改名：`send` 不再对外（只有内部防抖定时器调它），`schedule` → `input_changed`，`cancel` → `dispose`（见 [spec.md](../main-keyboard/spec.md) §3）。
- 判据在 2026-09-14 收口过一次（原文写的是「合成期间所有被拦截的键一律放行」，那要求 keydown 能判出合成状态）。当前口径见 Answer 第一条。
