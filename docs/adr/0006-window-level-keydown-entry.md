# 主窗口的按键收在一个 window 级入口后面

主面板只有一个输入框，但按键不能挂在它身上：`Preview` 打开时 input 不接受输入，鼠标点过 body 之后焦点也不在它身上，按键却都要照常生效——挂在 input 上就会漏掉这些情形。而且「这一次按键该不该拦」与「拦下之后状态怎么变」是两件事，混在事件回调里就没法各自验证。所以按键只在 `window` 捕获阶段的单个 `keydown` 监听里接收，映射交给纯函数 `resolve_key(key, mod, ctx) → Intent | null`，状态变化交给 `reduce`，接线（防抖、请求令牌、预请求、invoke）只留在 `useMainInteraction` 一处；副作用一律在事件回调里执行，不进 reducer / state updater——开发模式下它们会被调用两次，副作用放在那里就是一次按键打两枪。与之配套的是判定点归属：退场、失焦隐藏、触发动作后是否隐藏、显示时聚焦并全选，全部在 Rust 侧按 `Config` 与窗口事件决定，前端只表达意图。
