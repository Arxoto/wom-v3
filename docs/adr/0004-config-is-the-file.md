# 配置只有两种类型：Config 与 EditableConfig

`Config` 与持久化文件一一对应，同时就是运行时配置的唯一依据；派生值（窗口尺寸、生效的窗口效果）一律用方法现算，不再维护第二份运行时结构——两份结构会各自漂移，而且"文件里没有、内存里有"的字段已经误导过一次排查。前端拿到的是 `Config` 的子集 `EditableConfig`（视觉效果、布局、快捷键），整份读、整份写：写前严格校验、写后立刻生效并广播变更。项目还在开发期，所以升级一律按破坏性处理：不写 `version` 字段、不写迁移函数，旧文件里未知的键忽略、缺失的字段取默认值。
